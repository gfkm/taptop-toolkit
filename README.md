# Taptop Toolkit

**Taptop Toolkit переносит готовые сайты (HTML) и макеты из Figma в [Taptop](https://taptop.pro).** Страница вставляется в редактор Taptop целиком, и дальше её можно редактировать как обычную: каждый блок, заголовок, абзац, кнопка и картинка становятся отдельными элементами Taptop — со своими стилями и версиями для компьютера, планшета и телефона.

*English: Taptop Toolkit turns HTML/CSS sites and Figma designs into editable Taptop pages. It works with an AI assistant and the Taptop Toolkit Importer Chrome extension.*

---

## Как это работает — в трёх шагах

1. **Вы говорите ИИ-ассистенту, что перенести.** Подойдёт любой из вариантов:
   - файлы готового сайта — перетащите их в чат;
   - ссылка на сайт в интернете;
   - ссылка на макет в Figma — с UI-китом или только с экранами;
   - описание, если дизайна ещё нет: ассистент сам предложит дизайн и после вашего «да» перенесёт его.
2. **Ассистент превращает исходник в файл для Taptop.** Он сам запускает Toolkit, а Toolkit переводит сайт на «язык» Taptop: раскладывает страницу на блоки, тексты и картинки и собирает стили. В конце ассистент показывает, как страница будет выглядеть, и отдаёт готовый файл.
3. **Вы загружаете этот файл в Taptop.** Открываете страницу в редакторе Taptop, нажимаете кнопку расширения и выбираете файл. Страница появляется в редакторе — остаётся проверить её и сохранить.

Для этого нужны три вещи:

| Что | Зачем | Нужно ли |
| --- | --- | --- |
| **ИИ-ассистент** — Claude Code или Codex | Это тот, кто делает всю работу. Вы пишете ему обычными словами, а он разбирает исходник, запускает Toolkit и говорит, что получилось | **Обязательно.** Без ассистента система не работает |
| **Taptop Toolkit** — этот репозиторий | Набор инструментов, которыми пользуется ассистент: переводит сайт в формат Taptop и проверяет, что ничего не потерялось | **Обязательно** |
| **[Taptop Toolkit Importer](https://github.com/staumakes/taptop-toolkit-importer)** | Расширение для Chrome: загружает готовый файл в редактор Taptop | **Обязательно.** Без него страница в Taptop не попадёт |

Подойдёт не любой чат с нейросетью, а именно **Claude Code или Codex**: они умеют открывать папки на вашем компьютере, запускать программы и работать с файлами проекта.

### Несколько слов, которые встретятся дальше

- **Слой** — любой элемент страницы в редакторе Taptop: блок, текст, кнопка, картинка.
- **Класс** — набор стилей (цвет, шрифт, отступы), который можно повесить на много слоёв сразу. Поменяли класс — поменялись все слои с ним.
- **UI-кит** — страница-справочник со всеми цветами, шрифтами, кнопками и стилями текста сайта. Ассистент собирает его первым, и все страницы используют его классы.
- **Адаптив** — версии страницы для разных экранов. В Taptop это холсты «Компьютер», «Планшет», «Мобильный горизонтальный» и «Мобильный портретный».
- **MCP** — способ подключить к ИИ-ассистенту внешний сервис, например Figma, чтобы ассистент мог сам читать макеты.

| **Аккаунт Taptop** с доступом к проекту, куда переносите | [taptop.pro](https://taptop.pro) | По тарифам Taptop |

Сам Toolkit бесплатный, его код открыт. Программировать уметь не нужно: всё делает ассистент.

К ассистенту можно подключать и другие MCP-серверы, если они помогают вашей задаче.

## Установка — один раз

### 1. Скачайте Toolkit

На этой странице нажмите зелёную кнопку **Code → Download ZIP** и распакуйте архив в постоянное место, например в «Документы»: в этой папке будут храниться ваши проекты.

### 2. Откройте папку в ассистенте

- **Приложение Claude:** вкладка **Code** → выберите распакованную папку `taptop-toolkit-main`.
- **Codex:** откройте в нём эту папку.
- **Терминал:** перейдите в папку (`cd путь/к/taptop-toolkit-main`) и запустите `claude` или `codex`.

Напишите ассистенту: **«Установи Toolkit»**. Он сам всё поставит и проверит. Если Node.js не установлен, ассистент скажет об этом.

Ассистент сам найдёт в папке инструкцию, как работать с Toolkit, — настраивать больше ничего не нужно.

### 3. Установите расширение для Chrome

Отдельная пошаговая инструкция — в [README расширения](https://github.com/staumakes/taptop-toolkit-importer#установка). Коротко:

1. Скачайте [taptop-toolkit-importer](https://github.com/staumakes/taptop-toolkit-importer) (**Code → Download ZIP**), распакуйте и положите туда же, где Toolkit. Эту папку тоже нельзя удалять: Chrome берёт расширение прямо из неё.
2. Откройте в Chrome адрес `chrome://extensions` и включите **«Режим разработчика»** справа вверху.
3. Нажмите **«Загрузить распакованное расширение»** и выберите папку **`src`** внутри `taptop-toolkit-importer-main`.
4. Откройте любой проект в редакторе Taptop — в правом нижнем углу появится круглая синяя кнопка.

### 4. Готово — пишите в чат

Всё установлено. Теперь просто пишите ассистенту, что нужно сделать. Вот с чего можно начать:

| Что у вас есть | Что написать ассистенту |
| --- | --- |
| Готовый сайт | «Перенеси этот сайт в Taptop» — и приложите файлы или дайте ссылку |
| Макет в Figma с UI-китом | «Сделай UI-кит и главную страницу из этого макета: <ссылка>» |
| Макет в Figma, только экраны | «Собери UI-кит из экранов и перенеси их» |
| Дизайна ещё нет | «Предложи дизайн лендинга про …» — ассистент покажет вариант и после вашего «да» перенесёт |
| Начатый проект | «Продолжи работу над сайтом» или «Добавь страницу “Тарифы”» |
| В Taptop что-то не так | «На телефоне съехали кнопки» — лучше со скриншотом |

Если в исходнике чего-то нет — например, как кнопка выглядит при наведении или какой будет мобильная версия, — ассистент не будет это придумывать, а отметит пробел и скажет вам.

## Как перенести страницу

### 1. Отдайте исходник ассистенту

Откройте папку Toolkit в ассистенте и напишите, что нужно.

- **Готовый сайт:** перетащите в чат `index.html`, файлы стилей и папку с картинками или напишите, где они лежат: «Файлы лендинга в папке Документы/лендинг, перенеси его в Taptop».
- **Сайт есть только в интернете:** дайте ссылку — ассистент попробует сохранить страницу сам. Переносите только сайты, на которые у вас есть права.
- **Макет в Figma:** «Перенеси в Taptop этот макет: <ссылка>».

Дальше ассистент всё сделает сам: заведёт проект, соберёт UI-кит и страницу, сравнит результат с оригиналом на всех размерах экрана и скажет, если что-то отличается. В конце он назовёт файлы для загрузки. Они лежат в папке Toolkit: `projects/<название проекта>/output/json/`.

### 2. Загрузите в Taptop

Ассистент даст два файла: **UI-кит** и **страницу**. Сначала загрузите UI-кит, потом страницу — каждый на свою страницу Taptop:

1. **UI-кит** — создайте в Taptop отдельную страницу (например, «UI-кит»), нажмите на ней синюю кнопку расширения и выберите файл `ui-kit…json`.
2. **Страница** — откройте пустую страницу, куда переносите, и так же выберите файл `pages…json`.

### 3. Проверьте и сохраните

Посмотрите страницу на всех холстах (компьютер, планшет, телефоны) и нажмите **Cmd+S** (на Windows — **Ctrl+S**). Значок сохранения вверху должен стать зелёным. Если что-то не так — пришлите ассистенту скриншот, он разберётся.

## Что переносится

| Что есть на сайте | Что получится в Taptop | Проверено |
| --- | --- | --- |
| Блоки и секции | Блоки со своими классами | В Taptop |
| Заголовки и абзацы | Текстовые слои | В Taptop |
| Текст с выделениями — жирным, курсивом, ссылками внутри | Rich Text | В Taptop |
| Ссылки и кнопки | Ссылки, кнопки, кликабельные блоки | В Taptop |
| Картинки (PNG, JPEG, WebP, GIF) | Картинки. Файлы сами загружаются в медиатеку проекта | В Taptop |
| SVG-иконки | SVG Icon | В Taptop |
| Версии для разных экранов | Холсты Taptop: компьютер, планшет, два мобильных | В Taptop |
| Эффекты при наведении и нажатии | Состояния классов | В Taptop |
| Шрифты | По названию — шрифты уже есть в Taptop | В Taptop |
| Сложные стили: градиенты, тени, анимации | Классы, а что классы не умеют — точные стили в служебном слое `Scripts` | В Taptop |
| Раскрывающиеся вопросы (FAQ, аккордеон) | Обычные слои + скрипт, который их раскрывает | Перенос — в Taptop, раскрытие — на опубликованном сайте |
| Мобильное меню | Обычные слои + скрипт | Пока только на компьютере |

Служебный слой `Scripts` появляется в конце страницы. В нём лежат стили и скрипты, которые работают на опубликованном сайте. В редакторе вы правите обычные слои.

## Что пока не переносится

- **Слайдеры и карусели.** Каждый слайдер ассистент разбирает **отдельно, по его коду**: собирает слайды из обычных слоёв и подключает к ним поведение. Сам по себе слайдер не переедет.
- **Вкладки (табы), формы** заявок и подписки, **встроенные видео и карты**, **виджеты сторонних сервисов**. Toolkit явно скажет, что такой блок перенести нельзя.
- **Коллекции CMS и магазин Taptop.**
- **Скрипты с исходного сайта.** Они всегда удаляются: переносится внешний вид, а интерактив — только из списка выше.
- **Свои файлы шрифтов.** Если сайт использует шрифт, загруженный файлом, загрузите этот шрифт в проект Taptop. Toolkit предупредит.
- **SEO-настройки** — описание страницы и превью для соцсетей. Их настраивают в Taptop.
- **Замена уже вставленной страницы.** Расширение всегда добавляет новую копию в конец страницы. Старую удалите вручную.

## Почему результату можно доверять

- **Ничего не придумывается.** Чего нет в исходнике, того не будет и в результате — ассистент об этом скажет.
- **Один стиль на весь сайт.** Сначала собирается UI-кит, и все страницы используют его классы. Поменяли цвет кнопки в UI-ките — он поменяется везде.
- **Учтены особенности Taptop.** Toolkit знает, что Taptop хранит иначе, чем браузер, и заранее это обходит. Каждая такая особенность найдена на настоящем переносе и закреплена тестом.
- **Каждая ошибка исправляется навсегда.** Если что-то перенеслось неправильно, ассистент чинит не вашу страницу вручную, а сам Toolkit. Следующий перенос эту ошибку уже не повторит.
- **Проверка на всех экранах.** Перед загрузкой Toolkit сравнивает результат с оригиналом на восьми ширинах экрана.

## Когда страница готова

| Этап | Что это значит |
| --- | --- |
| **Собрано** | Toolkit подготовил файл для Taptop без ошибок |
| **Проверено на компьютере** | Предпросмотр совпал с оригиналом на всех размерах экрана |
| **Проверено в Taptop** | Страница загружена, просмотрена на всех холстах, сохранена и после перезагрузки на месте |
| **Проверено на сайте** | Опубликованная страница работает. Публикуют только с вашего согласия |

## Частые вопросы

**Нужно ли уметь программировать?** Нет. Вы пишете ассистенту обычными словами, команды он запускает сам.

**Подойдёт обычный ChatGPT или Claude в браузере?** Нет. Нужен Claude Code или Codex: только они умеют открывать папки на компьютере и запускать программы.

**Где хранятся мои проекты?** В папке Toolkit, внутри `projects/`. У каждого сайта своя папка.

**Как обновить Toolkit и не потерять проекты?** Скачайте новую версию, распакуйте рядом и перенесите в неё папку `projects` из старой. Или попросите ассистента: «Обнови Toolkit, мои проекты должны остаться».

**Почему страница в Taptop появилась второй раз?** Расширение всегда добавляет новую копию в конец страницы. Удалите старую копию в слоях Taptop. Стили при повторной загрузке не дублируются, а обновляются.

**Можно перенести чужой сайт?** Технически — да, но переносите только сайты, на которые у вас есть права.

**Шрифт в Taptop не тот.** Если на сайте был свой файл шрифта, загрузите этот шрифт в настройках проекта Taptop. Ассистент предупредит, какой именно.

## Если что-то не работает

- Напишите ассистенту, что не так. Он сам проверит проект и найдёт причину.
- Частые проблемы и решения — в [troubleshooting](system/docs/troubleshooting.md).
- Если пишете о проблеме публично, **не прикладывайте** файлы клиентов и ссылки на редактор Taptop: в них есть ключ доступа (`access=`).

## Для продвинутых

### Команды

Ассистент запускает всё сам, но команды можно вызывать и вручную — из папки Toolkit через `npm run toolkit -- <команда>`. Полный список — в [справочнике команд](system/docs/cli-reference.md).

```sh
npm run toolkit -- init projects/my-site my-site              # новый проект
npm run toolkit -- projects                                   # список проектов
npm run toolkit -- next --project projects/my-site            # какой шаг следующий
npm run toolkit -- doctor --project projects/my-site          # проверка проекта
npm run toolkit -- build --project projects/my-site --artifact pages/home
npm run toolkit -- serve                                      # предпросмотр на http://127.0.0.1:4320
```

Пошаговый пример со всеми командами: [getting started](system/docs/getting-started.md). Его примеры написаны для терминала macOS и Linux; на Windows используйте Git Bash или WSL. Автотесты гоняются на macOS и Linux.

### Где лежит результат

```text
projects/my-site/
  input/          исходники — Toolkit их не меняет
  design-system/  значения проекта: цвета, шрифты, стили (kit.json, roles.css)
  source/         список страниц, сгенерированный UI-кит
  output/html/    предпросмотр и страница результатов index.html
  output/json/    файлы для загрузки в Taptop
  .taptop/        служебные данные сборок
```

У каждого проекта своя дизайн-система: проекты ничего не делят между собой. Папка `projects/` в репозиторий не попадает. Подробнее: [структура проекта](system/docs/project-layout.md), [приём исходников](system/docs/source-intake.md).

### Как устроен перенос HTML

Любой HTML проходит через нормализатор. Всё, что Taptop умеет хранить, становится слоями и классами. Остальное уходит точными стилями в Embed, а то, что перенести нельзя, останавливает сборку с понятной причиной. Например, нормализатор:

- переименовывает классы, совпадающие с системными классами Taptop (`section`, `container`, `link` …), в `u-<имя>`;
- добавляет классы-уточнения там, где Taptop применяет классы в порядке имён, а не как в исходном CSS;
- отправляет «пользовательскими» значения, которые не держат обычные поля Taptop (`fit-content`, `clamp(…)`);
- режет стили на части, потому что Taptop не сохраняет Embed длиннее 50 000 символов.

Все правила и найденные факты о Taptop: [html-normalizer.md](system/docs/html-normalizer.md).

### Разработка

Код и правила — в `system/`, правила для участников и ассистентов — в [AGENTS.md](AGENTS.md), архитектура — в [architecture](system/docs/architecture.md). Перед изменением запускайте `npm test`.
