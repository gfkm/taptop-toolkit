# Taptop Toolkit

**Taptop Toolkit переносит готовый сайт или макет в [Taptop](https://taptop.pro) так, чтобы его можно было дальше редактировать.** Не картинкой и не куском кода, а обычной страницей: каждый блок, заголовок, абзац, кнопка и картинка становятся отдельными элементами редактора Taptop, со своими стилями и версиями для компьютера, планшета и телефона.

Что можно перенести:

- **готовую вёрстку** — свой сайт, лендинг, экспорт из Tilda или другого конструктора;
- **макет из Figma**;
- **дизайн, который предложил ИИ**.

*English: Taptop Toolkit turns HTML/CSS, Figma or AI-generated designs into editable Taptop pages. It works with an AI assistant and the Taptop Toolkit Importer Chrome extension.*

> **Статус:** ранняя версия `0.2.0-alpha.1`. Реальные страницы уже переносятся, но часть возможностей пока проверена только на компьютере, а не в самом Taptop. Это честно отмечено в списке ниже.

---

## Как это работает — в трёх шагах

1. **Вы даёте исходник и пишете задачу ИИ-ассистенту.** Например: «Перенеси этот лендинг в Taptop». Исходник — это файлы сайта или ссылка на макет в Figma.
2. **Ассистент готовит страницу с помощью Toolkit.** Он собирает файл для Taptop и показывает предпросмотр, как страница будет выглядеть. Toolkit следит, чтобы ничего не потерялось и не сломалось в Taptop.
3. **Расширение для Chrome загружает этот файл в Taptop.** Вы открываете редактор, нажимаете кнопку расширения, выбираете файл — страница появляется. Остаётся проверить её и сохранить.

Система состоит из трёх частей:

| Часть | Что это | Нужна ли |
| --- | --- | --- |
| **Taptop Toolkit** — этот репозиторий | Программа, которая готовит страницы для Taptop и проверяет их | Да |
| **[Taptop Toolkit Importer](https://github.com/staumakes/taptop-toolkit-importer)** | Расширение для Chrome. Загружает подготовленную страницу в редактор Taptop | **Да.** Без него страница в Taptop не попадёт |
| **ИИ-ассистент** — Claude Code или Codex | Делает всю работу по вашей просьбе: разбирает исходник, запускает Toolkit, объясняет результат | Очень желательно. Toolkit сделан так, чтобы им управлял ассистент |

### Несколько слов, которые встретятся дальше

- **Слой** — любой элемент страницы в редакторе Taptop: блок, текст, кнопка, картинка.
- **Класс** — набор стилей (цвет, шрифт, отступы), который можно повесить на много слоёв сразу. Поменяли класс — поменялись все слои с ним.
- **UI-кит** — страница-справочник со всеми цветами, шрифтами, кнопками и стилями текста сайта. С него всё начинается: страницы используют его классы.
- **Адаптив** — версии страницы для разных экранов. В Taptop это холсты «Компьютер», «Планшет», «Мобильный горизонтальный» и «Мобильный портретный».
- **JSON** — файл с подготовленной страницей. Его загружает расширение.
- **MCP** — способ подключить к ИИ-ассистенту внешний сервис, например Figma, чтобы ассистент мог сам читать макеты.

## Что понадобится

- **Компьютер** с Windows, macOS или Linux.
- **[Node.js](https://nodejs.org)** версии 22 или новее — бесплатная программа, ставится как обычное приложение. На ней работает Toolkit.
- **Google Chrome** и расширение **Taptop Toolkit Importer**.
- **ИИ-ассистент:** [Claude Code](https://claude.com/claude-code) или Codex.
- **Аккаунт Taptop** с доступом к проекту, куда переносите.
- **Для переноса из Figma:** платный тариф Figma и подключённый к ассистенту **Figma MCP**. Figma открывает MCP только платным местам (Dev или Full). Без этого ассистент не сможет читать макет — придётся выгружать из Figma картинки и значения вручную.

К ассистенту можно подключать и другие MCP-серверы, если они помогают вашей задаче.

## Установка — один раз

### 1. Toolkit

1. Скачайте этот репозиторий: зелёная кнопка **Code → Download ZIP**, затем распакуйте архив.
2. Откройте папку в терминале и выполните две команды:

   ```sh
   npm ci
   npm test
   ```

   Первая устанавливает всё нужное, вторая проверяет, что всё работает. Если в конце нет ошибок — готово.

### 2. Расширение для Chrome

1. Скачайте [taptop-toolkit-importer](https://github.com/staumakes/taptop-toolkit-importer): **Code → Download ZIP**, затем распакуйте.
2. Откройте в Chrome адрес `chrome://extensions`.
3. Включите **«Режим разработчика»** — переключатель справа вверху.
4. Нажмите **«Загрузить распакованное расширение»** и выберите папку **`src`** внутри распакованного архива.
5. Откройте любой проект в редакторе Taptop. В правом нижнем углу появится круглая синяя кнопка — расширение работает.

### 3. ИИ-ассистент

Откройте в ассистенте **всю папку Toolkit**. Больше ничего настраивать не нужно: в папке лежит инструкция для ассистента (она называется «навык»), и он найдёт её сам. В ней написано, какие команды запускать, в каком порядке и что проверять.

- **Claude Code** находит инструкцию через `CLAUDE.md`.
- **Codex** находит её через `AGENTS.md`.
- **Другому ассистенту** скажите: «Прочитай AGENTS.md и system/skills/taptop-site-transfer/SKILL.md».

## Как перенести страницу

Пример: у вас есть готовый лендинг — файл `index.html`, стили и картинки.

1. **Создайте проект.** В терминале в папке Toolkit:

   ```sh
   npm run toolkit -- init projects/my-site my-site
   ```

   `my-site` — название проекта, латиницей и без пробелов.

2. **Положите файлы сайта** в папку `projects/my-site/input/home/`. Toolkit их никогда не меняет — это ваш оригинал.

3. **Напишите ассистенту**, например:

   > Перенеси лендинг из projects/my-site/input/home в Taptop. Начни с UI-кита.

   Дальше ассистент сам:
   - соберёт UI-кит — цвета, шрифты, кнопки и стили текста;
   - соберёт страницу на классах UI-кита;
   - сравнит результат с оригиналом на всех размерах экрана и скажет, если что-то отличается.

4. **Посмотрите, что получилось.** Ассистент даст ссылку на страницу результатов. Там предпросмотр UI-кита и страниц и готовые файлы для Taptop.

5. **Загрузите в Taptop.** Откройте в редакторе Taptop страницу, куда переносите, нажмите синюю кнопку расширения и выберите файл. **Сначала UI-кит, потом страницы.** Файлы лежат в `projects/my-site/output/json/`.

6. **Проверьте и сохраните.** Посмотрите страницу на холстах «Компьютер», «Планшет», «Мобильный горизонтальный» и «Мобильный портретный», прокрутите до конца и нажмите **Cmd+S** (на Windows — **Ctrl+S**). Значок сохранения должен стать зелёным. Если что-то не так, пришлите ассистенту скриншот.

## Что ещё можно попросить у ассистента

| Ситуация | Что написать |
| --- | --- |
| Есть готовый сайт или экспорт из конструктора | «Перенеси эту страницу в projects/my-site» — и положите файлы в `input/` |
| Макет в Figma, в нём есть UI-кит | «Сделай UI-кит и главную страницу из этого макета: <ссылка>» |
| В Figma только экраны, без UI-кита | «Собери UI-кит из экранов и перенеси их» |
| Дизайна нет | «Предложи дизайн лендинга про …». Ассистент покажет варианты; после вашего «да» перенесёт |
| Нужно продолжить или добавить страницу | «Продолжи работу над projects/my-site» или «Добавь страницу “Тарифы”» |
| В Taptop что-то выглядит не так | «На телефоне съехали кнопки» — лучше со скриншотом |

Если в исходнике чего-то нет — например, как кнопка выглядит при наведении или как выглядит мобильная версия, — ассистент не будет это придумывать. Он отметит пробел и скажет вам.

## Что переносится

| Что есть на сайте | Что получится в Taptop | Проверено |
| --- | --- | --- |
| Блоки и секции | Блоки со своими классами | В Taptop |
| Заголовки и абзацы | Текстовые слои | В Taptop |
| Текст с выделениями — жирным, курсивом, ссылками внутри | Rich Text | В Taptop |
| Ссылки и кнопки | Ссылки, кнопки, кликабельные блоки | В Taptop |
| Картинки (PNG, JPEG, WebP, GIF) | Картинки. Файлы сами загружаются в медиатеку проекта | В Taptop |
| SVG-иконки | SVG Icon | В Taptop |
| Версии для разных экранов | Холсты Taptop: компьютер, планшет, два мобильных | В Taptop |
| Эффекты при наведении и нажатии | Состояния классов | В Taptop |
| Шрифты | По названию — шрифты уже есть в Taptop | В Taptop |
| Сложные стили: градиенты, тени, анимации | Классы, а что классы не умеют — точные стили в служебном слое `Scripts` | В Taptop |
| Раскрывающиеся вопросы (FAQ, аккордеон) | Обычные слои + скрипт, который их раскрывает | Перенос — в Taptop, раскрытие — на опубликованном сайте |
| Мобильное меню | Обычные слои + скрипт | Пока только на компьютере |
| Слайдеры, карусели, видео MP4 и анимации появления из Tilda | Обычные слои + скрипт | Пока только на компьютере |

Служебный слой `Scripts` появляется в конце страницы. В нём лежат стили и скрипты, которые работают на опубликованном сайте. В редакторе вы правите обычные слои.

## Что пока не переносится

- **Слайдеры и карусели**, кроме двух видов из Tilda. Каждый слайдер ассистент разбирает **отдельно, по его коду**: собирает слайды из обычных слоёв и подключает к ним поведение. Сам по себе слайдер не переедет.
- **Вкладки (табы), формы** заявок и подписки, **встроенные видео и карты**, **виджеты сторонних сервисов**. Toolkit явно скажет, что такой блок перенести нельзя.
- **Коллекции CMS и магазин Taptop.**
- **Скрипты с исходного сайта.** Они всегда удаляются. Переносится внешний вид, а интерактив — только из списка выше.
- **Свои файлы шрифтов.** Если сайт использует шрифт, загруженный файлом, загрузите этот шрифт в проект Taptop. Toolkit предупредит.
- **SEO-настройки** — описание страницы и превью для соцсетей. Их настраивают в Taptop.
- **Замена уже вставленной страницы.** Расширение всегда добавляет новую копию в конец страницы. Старую удалите вручную.

## Почему результату можно доверять

- **Ничего не придумывается.** Чего нет в исходнике, того не будет и в результате — ассистент об этом скажет.
- **Один стиль на весь сайт.** Сначала собирается UI-кит, и все страницы используют его классы. Поменяли цвет кнопки в UI-ките — он поменяется везде.
- **Учтены особенности Taptop.** Toolkit знает, что Taptop хранит иначе, чем браузер, и заранее это обходит. Каждая такая особенность найдена на настоящем переносе и закреплена тестом.
- **Каждая ошибка исправляется навсегда.** Если что-то перенеслось неправильно, ассистент чинит не вашу страницу вручную, а сам Toolkit. Следующий перенос эту ошибку уже не повторит.
- **Проверка на всех экранах.** Перед загрузкой Toolkit сравнивает результат с оригиналом на восьми ширинах экрана.

## Когда страница готова

| Этап | Что это значит |
| --- | --- |
| **Собрано** | Toolkit подготовил файл для Taptop без ошибок |
| **Проверено на компьютере** | Предпросмотр совпал с оригиналом на всех размерах экрана |
| **Проверено в Taptop** | Страница загружена, просмотрена на всех холстах, сохранена и после перезагрузки на месте |
| **Проверено на сайте** | Опубликованная страница работает. Публикуют только с вашего согласия |

## Если что-то не работает

- Попросите ассистента: «Проверь проект projects/my-site». Он запустит проверку и скажет, что не так.
- Частые проблемы и решения — в [troubleshooting](system/docs/troubleshooting.md).
- Если пишете о проблеме, **не прикладывайте** файлы клиентов и ссылки на редактор Taptop: в них есть ключ доступа (`access=`).

## Для продвинутых

### Команды

Все команды запускаются из папки Toolkit через `npm run toolkit -- <команда>`. Полный список — в [справочнике команд](system/docs/cli-reference.md).

```sh
npm run toolkit -- projects                                   # список проектов
npm run toolkit -- next --project projects/my-site            # какой шаг следующий
npm run toolkit -- doctor --project projects/my-site          # проверка проекта
npm run toolkit -- build --project projects/my-site --artifact pages/home
npm run toolkit -- serve                                      # предпросмотр на http://127.0.0.1:4320
```

Пошаговый пример со всеми командами: [getting started](system/docs/getting-started.md). Его примеры написаны для терминала macOS и Linux; на Windows используйте Git Bash или WSL. Автотесты гоняются на macOS и Linux.

### Где лежит результат

```text
projects/my-site/
  input/          ваши исходники — Toolkit их не меняет
  design-system/  значения проекта: цвета, шрифты, стили (kit.json, roles.css)
  source/         список страниц, сгенерированный UI-кит
  output/html/    предпросмотр и страница результатов index.html
  output/json/    файлы для загрузки в Taptop
  .taptop/        служебные данные сборок
```

У каждого проекта своя дизайн-система: проекты ничего не делят между собой. Папка `projects/` в репозиторий не попадает. Подробнее: [структура проекта](system/docs/project-layout.md), [приём исходников](system/docs/source-intake.md).

### Как устроен перенос HTML

Любой HTML проходит через нормализатор. Всё, что Taptop умеет хранить, становится слоями и классами. Остальное уходит точными стилями в Embed, а то, что перенести нельзя, останавливает сборку с понятной причиной. Например, нормализатор:

- переименовывает классы, совпадающие с системными классами Taptop (`section`, `container`, `link` …), в `u-<имя>`;
- добавляет классы-уточнения там, где Taptop применяет классы в порядке имён, а не как в исходном CSS;
- отправляет «пользовательскими» значения, которые не держат обычные поля Taptop (`fit-content`, `clamp(…)`);
- режет стили на части, потому что Taptop не сохраняет Embed длиннее 50 000 символов.

Все правила и найденные факты о Taptop: [html-normalizer.md](system/docs/html-normalizer.md).

### Разработка

Код и правила — в `system/`, правила для участников и ассистентов — в [AGENTS.md](AGENTS.md), архитектура — в [architecture](system/docs/architecture.md). Перед изменением запускайте `npm test`. Если меняется поведение, в той же правке обновляются инструкция ассистента и документация, затем `npm run docs:sync`.
