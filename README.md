# Taptop Toolkit

**Taptop Toolkit переносит сайт в [Taptop](https://taptop.pro) как настоящую редактируемую страницу**: слои, классы, адаптив под все экраны и картинки — так, будто страницу собрали в редакторе руками. Источником может быть готовая HTML/CSS-вёрстка, макет в Figma или дизайн, сгенерированный ИИ.

*English: Taptop Toolkit turns HTML/CSS, Figma or AI-generated designs into editable Taptop pages. It works with an AI assistant and the Taptop Toolkit Importer Chrome extension.*

> Статус: ранняя версия `0.2.0-alpha.1`. Система уже переносит реальные страницы, но часть возможностей проверена только локально — это честно отмечено ниже.

## Как это устроено

Система состоит из трёх частей. Работают они вместе:

```text
 Источник                 AI-ассистент              Taptop Toolkit                 Расширение Chrome           Taptop
 (HTML, Figma, ИИ)  ──▶  (Claude Code / Codex) ──▶  (эта папка: проверяет,   ──▶  Taptop Toolkit       ──▶  редактируемая
                          ведёт работу по шагам      собирает, сравнивает)          Importer                    страница
                                                     │                              (вставляет JSON
                                                     ├─ HTML-предпросмотр           в открытый редактор)
                                                     └─ JSON для импорта
```

| Часть | Что делает | Обязательна? |
| --- | --- | --- |
| **Taptop Toolkit** (этот репозиторий) | Хранит ваши проекты, приводит HTML/CSS к виду, который понимает Taptop, собирает UI-кит, страницы и пакет для импорта, сравнивает результат с оригиналом | Да |
| **Taptop Toolkit Importer** (отдельный репозиторий [taptop-toolkit-importer](https://github.com/staumakes/taptop-toolkit-importer)) | Расширение Chrome. В открытом редакторе Taptop проверяет пакет, загружает картинки в медиатеку, создаёт классы и вставляет слои | **Да.** Без него JSON в Taptop не попадёт |
| **AI-ассистент** — Claude Code или Codex | Читает инструкции Toolkit, вытаскивает значения из источника, запускает команды, объясняет, что получилось | Очень желательно: Toolkit написан так, чтобы им управлял ассистент |

Главная идея: **вы описываете задачу словами, ассистент делает работу, Toolkit не даёт ошибиться**. Toolkit сам решает, какой шаг следующий, отказывается собирать то, что сломается в Taptop, и показывает, где результат.

## Что понадобится

- Компьютер с macOS или Linux. Проверено на macOS.
- [Node.js](https://nodejs.org) версии 22 или новее. Проверить: `node -v`.
- Google Chrome.
- Аккаунт Taptop с доступом к редактору проекта, куда будете переносить.
- AI-ассистент: [Claude Code](https://claude.com/claude-code) или Codex. Для работы с Figma — подключённый к ассистенту Figma-коннектор.

## Установка — один раз

### 1. Toolkit

Скачайте этот репозиторий (кнопка **Code → Download ZIP** или `git clone`), откройте папку в терминале и выполните:

```sh
npm ci
npm test
```

`npm test` должен закончиться без ошибок — значит, всё установилось правильно.

### 2. Расширение Taptop Toolkit Importer

1. Скачайте репозиторий [taptop-toolkit-importer](https://github.com/staumakes/taptop-toolkit-importer): **Code → Download ZIP**, затем распакуйте.
2. Откройте в Chrome адрес `chrome://extensions` и включите **«Режим разработчика»** (переключатель справа вверху).
3. Нажмите **«Загрузить распакованное расширение»** и выберите папку `src` внутри скачанного репозитория.
4. Откройте любой проект в редакторе Taptop: в правом нижнем углу появится круглая синяя кнопка импорта. Значит, расширение работает.

После обновления расширения нажмите на его карточке в `chrome://extensions` кнопку обновления и перезагрузите вкладку редактора.

### 3. AI-ассистент

Откройте **всю папку Toolkit** (а не только папку проекта) в ассистенте. Дальше всё подключится само:

- **Claude Code** читает `CLAUDE.md` и находит навык (skill) `.claude/skills/taptop-site-transfer/`.
- **Codex** читает `AGENTS.md` и находит навык `.agents/skills/taptop-site-transfer/`.
- **Другой ассистент** — попросите его сначала прочитать `AGENTS.md` и `system/skills/taptop-site-transfer/SKILL.md`.

Навык — это пошаговая инструкция для ассистента: какие команды запускать, в каком порядке, что проверять и о чём спрашивать вас. Он обновляется вместе с Toolkit.

## Первый перенос за 10 минут

Пример: у вас есть свёрстанный лендинг — файл `index.html`, стили и картинки.

1. **Создайте проект.** В терминале в папке Toolkit:

   ```sh
   npm run toolkit -- init projects/my-site my-site
   ```

   Последнее слово — постоянное имя проекта (латиница, без пробелов).

2. **Положите исходники** в `projects/my-site/input/home/`: `index.html`, CSS-файлы, папку с картинками. Исходники Toolkit никогда не меняет.

3. **Скажите ассистенту**, например:

   > Перенеси лендинг из `projects/my-site/input/home` в Taptop. Сначала сделай UI-кит.

   Ассистент сам:
   - соберёт UI-кит (цвета, шрифты, кнопки, стили текста) из вашего CSS;
   - соберёт страницу, обязательно используя классы UI-кита;
   - сравнит результат с оригиналом на всех ширинах экрана и скажет, где отличия и почему.

4. **Посмотрите результат** в браузере. Запустите локальный сервер:

   ```sh
   npm run toolkit -- serve
   ```

   и откройте `http://127.0.0.1:4320/projects/my-site/output/html/index.html` — там предпросмотр UI-кита и каждой страницы, ссылка на JSON и инструмент сравнения с оригиналом.

5. **Импортируйте в Taptop.** Откройте нужную страницу в редакторе Taptop, нажмите синюю кнопку расширения и выберите файл:
   - сначала `output/json/ui-kit--<сборка>.json`,
   - потом `output/json/pages--home--<сборка>.json`.

   Расширение покажет, сколько будет слоёв, классов и картинок. Классы UI-кита на странице должны значиться как «уже есть» или «без изменений».

6. **Проверьте и сохраните.** Посмотрите холсты «Компьютер», «Планшет» (768), «Мобильный горизонтальный» (480) и «Мобильный портретный» (320), прокрутите страницу до конца и нажмите **Cmd+S**: индикатор сохранения должен стать зелёным. Расскажите ассистенту, что увидели, — он запишет проверку.

Полный пошаговый пример с синтетическими данными: [getting started](system/docs/getting-started.md).

## Сценарии работы

Во всех сценариях вы говорите с ассистентом обычными словами. Ниже — что сказать и что получится.

### А. Есть готовая HTML/CSS-вёрстка

Свёрстанный лендинг, экспорт из Tilda, Taptop или другого конструктора, страница, сохранённая из браузера.

> «Перенеси эту страницу в проект projects/my-site» (и положите файлы в `input/`).

HTML проходит через нормализатор: всё, что Taptop умеет хранить, становится слоями и классами; остальное — точными стилями в скрытом Embed; то, что перенести нельзя, останавливает сборку с понятной причиной. Ничего не теряется молча.

### Б. Макет в Figma с UI-китом

> «Сделай UI-кит и главную страницу из этого Figma-файла: <ссылка>».

Ассистент берёт значения из UI-кита макета (цвета, типографику, кнопки, состояния), собирает витрину UI-кита, затем страницы. Нужен Figma-коннектор в ассистенте.

### В. Макет в Figma без UI-кита

> «В Figma только экраны, без UI-кита. Собери UI-кит из повторяющихся значений и перенеси экраны».

Повторяющиеся значения и компоненты выводятся из экранов. Всё, чего на экранах нет (например, состояние наведения или мобильная версия), помечается как `MISSING` и не придумывается.

### Г. Дизайн, сгенерированный ИИ

> «Предложи дизайн лендинга для …» → вы утверждаете направление → «Перенеси в Taptop».

Сначала ассистент предлагает значения, вы их утверждаете, и только потом собираются страницы.

### Д. Продолжить, пересобрать, добавить страницу

> «Продолжи работу над projects/my-site» или «Добавь страницу “Тарифы”».

Toolkit сам знает, что сделано, а что нет (`npm run toolkit -- next`). Если поменялся UI-кит, зависимые страницы помечаются устаревшими и пересобираются.

### Е. Что-то выглядит не так

> «В Taptop кнопки съехали на мобильном» (лучше со скриншотом).

Ассистент ищет причину, а не правит результат вручную: каждая найденная ошибка превращается в правило Toolkit с тестом, и следующий перенос её уже не повторит.

## Что переносится

| В источнике | В Taptop | Проверено |
| --- | --- | --- |
| Блоки: `div`, `section`, `header`, `footer`, `nav`, `ul`/`li` и т. п. | Слой «Блок» с классом | В редакторе Taptop |
| Текст: `p`, `h1`–`h6`, `span` | Слой «Текст» | В редакторе |
| Текст с форматированием: жирный, курсив, переносы строк, ссылки и цветные фрагменты внутри | Слой **Rich Text** (виджет Taptop) | В редакторе |
| Ссылки, кнопки, кликабельные блоки | «Ссылка», «Кнопка», «Link Block» | В редакторе |
| Картинки PNG, JPEG, WebP, GIF | Слой «Картинка»; файлы сами загружаются в медиатеку проекта при импорте | В редакторе |
| Встроенные SVG-иконки | Виджет **SVG Icon** | В редакторе |
| Адаптив | Брейкпоинты Taptop: 991, 767 и 479 px. Остальные медиазапросы работают через скрытый Embed | В редакторе |
| Состояния `:hover`, `:focus`, `:active` | Состояния класса в Taptop | В редакторе |
| Шрифты | По названию: шрифты встроены в Taptop | В редакторе |
| Сложный CSS: вложенные селекторы, `::before`/`::after`, градиенты, анимации `@keyframes`, CSS-переменные | Классы Taptop, а то, что классы выразить не могут, — точными стилями в скрытом Embed | В редакторе |
| Аккордеон / FAQ (`<details>` или блок с `data-taptop-behavior="accordion"`) | Редактируемые слои + скрипт в скрытом Embed | Импорт — в редакторе; поведение — на опубликованной странице |
| Мобильное меню (блок с `data-taptop-behavior="menu"`) | Редактируемые слои + скрипт в Embed | Локально |
| Слайдеры Tilda `.t-slds` и карусели `t1196`, видео MP4 Tilda, анимации появления Tilda `t-animate` | Редактируемые слои + сгенерированный скрипт в Embed | Локально |

«Скрытый Embed» — служебный слой `Scripts` в конце страницы со стилями и скриптами. Скрипты работают на опубликованной странице, а в редакторе всё остаётся редактируемыми слоями.

## Что пока не поддерживается

- **Слайдеры и карусели**, кроме двух распознаваемых структур Tilda. Каждый такой слайдер разбирается **отдельно, по его собственному коду**: ассистент изучает разметку и скрипт, собирает слайды из обычных редактируемых слоёв и подключает поведение отдельным адаптером. Автоматически «как есть» слайдер не переносится.
- **Табы, формы** (заявки, подписки), **видеоплееры** (кроме MP4 из Tilda), **iframe, карты и виджеты сторонних сервисов**. Сборка явно сообщает о таких блоках.
- **CMS-коллекции и магазин Taptop.**
- **JavaScript исходной страницы.** Он всегда удаляется: в Taptop переносится вёрстка, а интерактив — только через адаптеры выше.
- **Собственные файлы шрифтов** (`@font-face` с локальным файлом). Шрифт нужно загрузить в проект Taptop — сборка предупредит (`FONT_FILE_RELATIVE`).
- **SEO и мета-теги** (`<meta>`, заголовок, превью для соцсетей) — настраиваются в Taptop отдельно.
- **Замена уже вставленной страницы.** Импорт всегда добавляет новые слои в конец страницы; старую версию удаляют вручную. Классы при повторном импорте обновляются.

## Как работает процесс внутри

Этот раздел объясняет, почему Toolkit устроен строго, — и почему ему можно доверять.

**1. Один проект — одна дизайн-система.** У каждого проекта свой UI-кит, свои значения, свои страницы. Проекты ничего не делят между собой. Если проектов несколько и вы не назвали нужный, ассистент обязан спросить.

**2. Сначала UI-кит, потом страницы.** UI-кит собирается генератором в одном и том же каркасе для любого проекта: ассистент только заполняет значения. Страницы обязаны использовать **ровно те же классы** UI-кита для текста, кнопок и ссылок. Если правила класса на странице расходятся с UI-китом, сборка откажет — сначала обновляется UI-кит.

**3. Ничего не придумывается.** Значение, которого нет в источнике, помечается `MISSING`, неоднозначное — `NEEDS HUMAN REVIEW`, неподдерживаемое — `UNSUPPORTED`. Пустоты не заполняются «на глаз» или из чужого проекта.

**4. Нормализатор вместо ручной правки.** Любой присланный HTML проходит через нормализатор. Он учитывает особенности Taptop, найденные на живых импортах. Например:
   - системные имена классов Taptop (`section`, `container`, `link` …) переименовываются в `u-<имя>`, иначе на них ляжет базовый стиль Taptop;
   - Taptop применяет классы в порядке имён, поэтому, где нужно, добавляются классы-уточнения;
   - значения, которые не держит обычное поле Taptop (`fit-content`, формулы `clamp`), отправляются как «пользовательские»;
   - Embed больше 50 000 символов Taptop не сохраняет, поэтому стили режутся на части.

   Полный список правил и фактов: [html-normalizer.md](system/docs/html-normalizer.md).

**5. Сборка повторяема.** Каждая сборка даёт пару «HTML-предпросмотр + JSON» с одним номером. Неудачная сборка не затирает предыдущую удачную. Если ничего не поменялось, новой сборки не будет.

**6. Toolkit сам подсказывает следующий шаг.** Команда `npm run toolkit -- next --project projects/<папка>` по файлам на диске говорит, что делать дальше: подготовить UI-кит, собрать, проверить, импортировать. Ассистент работает по ней.

**7. Каждая ошибка становится правилом.** Если в Taptop что-то выглядит не так, ассистент ищет механизм, пишет тест, исправляет генератор и записывает факт о Taptop с датой. Ручная правка JSON не считается решением.

## Где лежит результат

Всё внутри папки проекта:

- `output/html/index.html` — страница результатов: каждая страница и UI-кит со статусом, предпросмотром, JSON и записанными проверками;
- `output/html/<страница>--<сборка>/page.html` — предпросмотр того, что получится в Taptop;
- `output/json/<страница>--<сборка>.json` — файл для импорта расширением.

Смотреть предпросмотр и сравнение с оригиналом удобнее через `npm run toolkit -- serve`.

## Когда работа считается готовой

| Уровень | Что это значит |
| --- | --- |
| **Собрано** | `build` прошёл: страница нормализована, собрана и проверена перед импортом |
| **Проверено локально** | Сравнение с оригиналом на ширинах 1440/992/768/480/320 и 900/700/375 — без необъяснённых отличий |
| **Проверено в редакторе** | Импортировано в Taptop, просмотрены 4 холста, страница сохранена и перезагружена |
| **Проверено на сайте** | Опубликованная страница работает. Публикуется только с вашего согласия |

Каждый уровень записывается командой `check`. Ассистент не имеет права записать проверку в редакторе, которую не видели вы или он сам.

## Если что-то пошло не так

- Проверка состояния проекта: `npm run toolkit -- doctor --project projects/<папка>`.
- Частые ошибки и что с ними делать: [troubleshooting](system/docs/troubleshooting.md).
- Обновление Toolkit: [updating](system/docs/updating.md). Проект запоминает версию Toolkit — не меняйте её вручную.
- Сообщая о проблеме, приложите версии, шаг, на котором всё сломалось, вывод `doctor` и упрощённый пример. **Не публикуйте** файлы клиентов, ссылки на редактор Taptop (в них есть ключ доступа `access=`), cookies и файлы импорта.

## Структура папок

```text
taptop-toolkit/
  README.md, AGENTS.md, CLAUDE.md   описание и правила для людей и ассистентов
  system/                           инструменты Toolkit: код, правила, навык, документация, тесты
  projects/                         ваши проекты (в репозиторий не попадают)
    my-site/
      taptop.project.json           имя проекта и версия Toolkit
      input/                        ваши исходники — никогда не меняются
      design-system/                значения проекта: kit.json, roles.css, источники
      source/                       реестр страниц, сгенерированный UI-кит, страницы
      output/html/                  предпросмотры и страница результатов
      output/json/                  файлы для импорта
      .taptop/                      служебное состояние сборок
```

Подробнее: [структура проекта и сборки](system/docs/project-layout.md), [приём исходников](system/docs/source-intake.md).

## Для разработчиков

Код и правила — в `system/` (`bin/`, `lib/`, `contracts/`, `templates/`, `examples/`, `test/`, `skills/`, `docs/`). Правила для участников и ассистентов — в [AGENTS.md](AGENTS.md), архитектура — в [architecture](system/docs/architecture.md), все команды — в [справочнике CLI](system/docs/cli-reference.md). Перед любым изменением: `npm test`. Если меняется поведение, в той же правке обновляются навык и документация, затем `npm run docs:sync`.
