# Форк Taptop Toolkit

Ветка `fork` — форк [staumakes/taptop-toolkit](https://github.com/staumakes/taptop-toolkit) от коммита `e637a31`
(2026-10-13): история оригинала сохранена, все изменения форка — один коммит поверх неё. Лицензия оригинала (MIT)
сохранена. Пара к нему — форк импортёра [gfkm/taptop-toolkit-importer](https://github.com/gfkm/taptop-toolkit-importer),
ветка `fork`.

Зачем форк: у сайта, куда переносятся страницы, в Taptop уже есть свои классы, сделанные вручную (типографика,
кнопки, отступы), поэтому пакеты должны ссылаться на них по имени, а не привозить свой UI-кит. Сверх этого
понадобились поведения для анимированных иллюстраций и степперов, а живые импорты нашли несколько расхождений с
Taptop. Исходный HTML для Toolkit готовят отдельные конвертеры (из блоков Figma и с холстов с анимацией); в этот
форк они не входят.

## Что изменено относительно оригинала

| Что | Проверено |
|---|---|
| Тесты проходят на Windows без режима разработчика (ссылки на папки → junction) | `npm test` |
| Отказ при потерянном относительном `url()` (`URL_ASSET_LOST`); поведение `reveal`: CSS-анимация стартует, когда блок появился на экране | локально |
| `var()` в Embed-объявлениях больше не заменяется значением первого элемента (у всех элементов класса была одна задержка анимации) | локально |
| Внешние таблицы стилей: `artifact add --external-css` — классы сайта используются по имени, в пакет не попадают (`externalClasses`), переопределять их нельзя (`EXTERNAL_*`) | локально |
| `serve`: несколько папок под одним адресом (`mounts`) — проект вне `projects/` можно сравнивать без копирования | локально |
| Неразрывные пробелы доживают до пакета (компилятор схлопывал их как обычные); собственные классы Toolkit защищены от совпадения с классами сайта; сборка устаревает при смене кода Toolkit | локально |
| Embed не перебивает переопределения из исходника: один модуль `css-cascade.js` ранжирует объявления для классов и для Embed | локально |
| Поведение `steps` (`taptop/embed-steps-v1`) для степперов и вкладок: автопереключение 6 с, пауза при наведении / фокусе / вне экрана, клик останавливает навсегда, клавиатура и ARIA, кнопка копирования | в тестовом DOM и в headless-браузере; в Taptop не проверено |
| `transform-box` уходит в Embed: класс Taptop его не сохраняет, и живой импорт падал целиком | тест; повторный живой импорт ещё не сделан |
| Имена слоёв: атрибут `data-taptop-name`, иначе первый собственный класс, а не последний служебный (`…--sel`); UI-кит сохраняет прежние имена | тесты; в редакторе не проверено |
| Картинка получает браузерный `overflow: clip` через Embed (базовый `overflow: hidden` Taptop давал flex-контейнеру сжать картинку) | локально; на опубликованной странице не проверено |

`npm test`: 508 тестов, 503 проходят, 5 пропущены (ссылки на файлы на Windows без режима разработчика).

## Что проверено вживую в Taptop

Мало, это главное ограничение форка. Первые импорты на тестовую страницу сделаны 2026-10-19: классы одной иллюстрации
дошли до стилей проекта, другой импорт упал на `transform-box` (исправлено, повторный импорт ещё не сделан). Не
проверены в живом редакторе или на опубликованной странице: поведение `steps`, имена слоёв, `overflow` картинок,
порядок применения классов Taptop с `_` и `-` в имени. Подробности по каждому правилу — в
`system/docs/html-normalizer.md` (таблицы правил, фактов Taptop и «Known limits»).

## Совместимость с оригиналом

Формат пакета остался версии 2. Пакет, где есть `externalClasses` или поведение `steps`, нужно загружать импортёром из
форка `gfkm/taptop-toolkit-importer`: оригинальный импортёр о них не знает. Новые коды отчёта нормализатора и сборки
описаны в `system/docs/troubleshooting.md`.
