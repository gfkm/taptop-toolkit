# Проект Taptop

Этот проект принадлежит пользователю. Инструменты Toolkit находятся отдельно (папка `system/` Toolkit); их правила в корневом `AGENTS.md` Toolkit обязательны, порядок работы — скил Toolkit `../../system/skills/taptop-site-transfer/SKILL.md` (путь от папки проекта внутри `projects/`). Открывай в AI-клиенте папку Toolkit, а не только папку проекта: так подключаются скил и правила.
Перед работой прочитай `taptop.project.json` и выполни из папки Toolkit `npm run toolkit -- doctor --project projects/<эта-папка>`.
Все команды получают этот проект явно (`--project projects/<эта-папка>`); никогда не переключайся на соседний проект и не используй значения другого проекта.
Не меняй закреплённую версию Toolkit (`toolkitVersion`) вручную.
Дизайн-система изначально пустая. Значения и компоненты извлекаются только из предоставленного пользователем источника; не придумывай дизайн или контент. Недостающее помечается `MISSING`, при отсутствии мобильных макетов — `MISSING RESPONSIVE DESIGN`.
Оригиналы лежат в `input/` и не меняются. Присланный HTML проходит через нормализатор в составе `build`; результаты появляются в `output/html/` и `output/json/` с одинаковым ID сборки.
Сначала собирается UI Kit (`ui-kit`, затем `build --artifact ui-kit`), потом страницы с точными классами кита (`design-system/roles.css` первым стилем, `--depends ui-kit`).
Уровни проверки раздельны: сборка, локальное сравнение, проверка в редакторе Taptop, опубликованная страница. Каждый записывается командой `check`; успешная сборка не доказывает импорт.
Неподдерживаемую интерактивность нельзя незаметно заменять статикой.
Никогда не переносить target IDs, токены доступа или receipts между проектами.
