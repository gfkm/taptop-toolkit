# Границы первой версии

Обновлено 2026-10-09. Пути ниже отсчитываются от `system/`, если не указано иное. Актуальная программа миграции — the maintainers' development plan (`system/docs/superpowers/`, kept out of the distribution), состояние новой структуры — [project layout](project-layout.md).

## Общие части

lib/compiler — HTML → промежуточная модель → Taptop. lib/css-* и rule-sets — существующие правила сериализации CSS. lib/*contract*, validate-* и preflight — машинные проверки. contracts/ — версия переносимых данных. lib/project и compile-project — безопасная локальная точка входа.

## Извлечённое и изменённое

Исходные модули взяты из локального taptop-export; hashes на момент извлечения записаны в extraction-provenance.json. Конвертер больше не читает build-typography-classes.js и typography-tokens-reference.css. Пользовательские классы типографики проходят общий CSS-конвейер. Из identity builder дополнительно экспортирован selectorUsesClass для проверки наличия управляемых правил.

Реестр поведений сохраняет известные adapter IDs, но в этой автономной поставке их статус research-required: частные наблюдения из редактора не копировались. Проверки не ослаблялись ради объявления этих адаптеров готовыми.

Скопированы самодостаточные тесты исходного ядра. Названия путей html-export в отдельных тестах — синтетические строки фикстур, а не зависимость от папки автора.

## Пользовательские данные

templates/project создаёт пустые design-system/foundations.json и registry.json, пустой реестр артефактов `source/artifacts.json`, отдельные `input/`, `source/`, `output/html/`, `output/json/` и `.taptop/`. Целевые привязки импорта хранятся в localStorage редактора (импортёр), а не в проекте, и не входят в переносимый пакет.

## Управляемая сборка

`lib/project-artifacts.js` — реестр артефактов (ui-kit, components/*, pages/*). `lib/build-artifact.js` — блокировка проекта (`lib/project-lock.js`), нормализация в стабильный `.taptop/work/<артефакт>/`, компиляция с проектными ключами классов `<namespace>/class/<имя>`, проверка общих классов против кита и других артефактов, публикация пары HTML/JSON и запись каталога `.taptop/outputs.json` последней (`lib/output-catalog.js`). `lib/doctor-project.js` — диагностика только для чтения, `lib/record-check.js` — раздельные уровни проверки, `lib/static-server.js` — локальный сервер на 127.0.0.1. Прежние `normalize`/`compile` и ключи `<componentKey>/class/<имя>` сохранены для старых проектов.

## Совместимость и обновления

Текущая защита — точное совпадение toolkitVersion и schemaVersion; см. `docs/updating.md`. Совместимость с импортёром определяется форматом пакета (version 2) и возможностями; синтетические пакеты управляемой сборки экспортирует `scripts/export-compatibility-fixtures.js`. Обновление инструмента не меняет CSS, словарь или контент проекта. Миграции должны быть явными, с резервной копией и отчётом.

## Оставшиеся этапы

1. Живая проверка в редакторе Taptop на одноразовых проектах: кит, затем страница, повторный импорт, сохранение и перезагрузка; запись `check --level editor`.
2. Оценка навыка свежим агентом на сценариях (несколько проектов, отсутствующие данные, просьбы обойти нормализатор).
3. Публичная лицензия и проверка происхождения включённых модулей (особенно class-sync из Helper), CI, релизы и страница расширения.

Для этого этапа выбран узкий CLI-профиль: лучше явная ошибка, чем обещание поддержки произвольного HTML. Даже прошедший preflight пакет требует визуальной и функциональной проверки в Taptop.
