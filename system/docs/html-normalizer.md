# HTML normalizer — rules

Every HTML/CSS page a user sends goes through the normalizer before compiling.
Nobody hand-edits a user's page into the compiler profile. The normalizer is
deterministic, keeps the user's files untouched, and reports every change.

Managed projects (layout version 2) run it as part of every build:

```sh
npm run toolkit -- artifact add --project projects/<folder> --key pages/<name> --html input/<name>/index.html --css design-system/roles.css --css input/<name>/styles.css --depends ui-kit
npm run toolkit -- build --project projects/<folder> --artifact pages/<name>
```

The build normalizes into `.taptop/work/<artifact>/` (a stable, tool-owned folder that is replaced on each build; its path takes part in the source revision, so it never contains a build ID) and publishes a copy with the preview to `output/html/<artifact>--<build>/`. Several stylesheets are one cascade in the listed order. A stylesheet registered with `--external-css` belongs to the target site and comes first in that cascade (see "External stylesheets" below). Legacy single-page projects keep the original commands, which write `source/normalized/` once:

```sh
npm run toolkit -- normalize <project> <html> <css> [--root .class]
npm run toolkit -- compile <project> source/normalized/manifest.json <new-output.json>
```

Files produced in either location (legacy location never overwritten):

| File | Purpose |
| --- | --- |
| `page.html` | Prepared HTML: classes, stable `data-taptop-key`, `data-taptop-name` where a layer name differs from the last class ([Layer names](#layer-names)), portable attributes only |
| `page.css` | Single-class rules and `:hover/:focus/:focus-visible/:active` states on Toolkit breakpoints |
| `page.embed.css` | CSS Taptop classes cannot express; ships as one hidden Embed in `Scripts` |
| `behaviors.json` | Declared behaviors (accordion, menu, reveal, steps, supported Tilda slider/carousel and MP4 video structures, plus Tilda viewport reveals) for generated Embed scripts |
| `manifest.json` | Compiler manifest incl. `selectorMappings`, `behaviorManifest`, `embedStylesheet`, `externalClasses` |
| `normalization-report.json` | Every decision: `level`, `code`, `decision`, `reason`, samples |
| `taptop-preview.css` | Taptop page defaults for local preview only; never packaged |

## Principles

1. **Nothing is lost silently.** A rule is either converted to a Taptop class,
   moved verbatim into the embed stylesheet, or reported as an error.
2. **Editable first.** Visible structure becomes ordinary Taptop layers and
   classes; behavior and relational CSS go to Embed and work on the published page.
3. **Fail closed.** Unsupported content is an `error` and blocks compiling until
   the source is fixed or an adapter exists.
4. **Prove fidelity.** Compare original and normalized pages with
   `system/docs/tools/normalize-compare.html` at 1440/992/768/480/320 and
   900/700/375 before import (`npm run toolkit -- serve`, then the `links.compare`
   URL printed by `build`). Zero differences is the target; any difference is
   explained in the report. The tool matches elements by `data-taptop-key` when
   the original has keys, otherwise by document order, and reports how many
   elements it compared: zero compared elements is a failed comparison. It treats
   the documented `FONT_NAME` and text blockification (`TAPTOP_BASE_RESET`)
   results as equal, skips the generated `.page` wrapper (`ROOT_WRAPPED`), and
   reports “font not installed locally” when a page font renders in a fallback —
   text sizes are then not comparable until the font is installed or linked.

## Transformations

| Source | Result | Report code |
| --- | --- | --- |
| Grouped selectors `.a, .b` | One rule per selector | `GROUP_SPLIT` |
| `@media [only] screen and (max-width: 991/767/479px)` | Toolkit breakpoints | — |
| Other media (`min-width`, other widths, `prefers-reduced-motion`) | Embed, same media | `MEDIA_TO_EMBED` |
| `.class` | Class rule | — |
| `.class:hover/:focus/:focus-visible/:active` | Taptop state rule (`cm` channel) | — |
| Relational, compound, attribute and structural selectors (`#hero > div[aria-hidden] > div:nth-child(3)`, `.a.b`, `.a .b + .b`, `ul li:first-child`) | Matched on the source page (ids, attributes and structure as written); the elements it reaches get `<class>--sel[-b …]` and the rule becomes a class rule with the selector's specificity. Same-element compounds such as `.a.b` must be lowered too: leaving them in the later Embed stylesheet can override the imported class color or background. `:hover`/`:focus`/`:active` of the matched layer → a Taptop state rule; `::before`/`::after`, other states, markup inside Rich Text/SVG Icon and media queries without a Taptop breakpoint → embed on that class | `SELECTOR_LOWERED` |
| Selectors with script-toggled states (`.is-*`, `.active`, `.open`, `[aria-expanded]` …), dynamic parts before the last element (`.card:hover .title`), unsupported syntax, or nothing matched on the page | Embed, verbatim | `SELECTOR_TO_EMBED` |
| `body` | Inherited text settings and background lifted to the root class | `GLOBAL_RULE_LOWERED` |
| Element selectors (`h1`, `p` …) | Applied to the classes of those elements; class values win | `GLOBAL_RULE_LOWERED` |
| `*` `box-sizing: border-box` | Removed — Taptop pages already use it | `GLOBAL_RULE_LOWERED` |
| `html`, other `*` declarations | Embed | `GLOBAL_RULE_LOWERED` |
| `@keyframes`, `@font-face`, other at-rules | Embed | `AT_RULE_TO_EMBED` |
| `var(--x)` with a value on `:root`, on a class rule or in an inline style of an ancestor | Literal value, inherited through the DOM as in the browser; a class used under different values keeps its first element's value | `VARIABLE_CONTEXT` (warning) when contexts differ |
| Custom-property definitions and every declaration using `var()` (except a `var()` with one value for its whole class, next row) | Also copied to the Embed stylesheet, while the class retains its resolved fallback. This preserves values set by a parent, an id/relational selector or a breakpoint that a Taptop class cannot represent. The definitions are written once, as one block at the top of the Embed: every custom-property rule that can reach an element of the page, in source order, inline styles last (before 2026-10-19 each rule repeated its definitions further down, and an inline definition lost to a later class definition of the same variable). A declaration that lives only in the Embed (animation, `url()`, auto side margins) gets its resolved value first and the `var()` form after it, so each element keeps its own variable value (before 2026-10-15 the resolved value came last and every element animated with the first element's delay). A rule the Embed carries whole (a media query that is not a Toolkit breakpoint, a relational selector left in the Embed, a pseudo-element) writes each `var()` declaration once, as written, in source order (before 2026-10-19 its resolved value followed it and won) | `CUSTOM_PROPERTY_TO_EMBED`, `VARIABLE_TO_EMBED` |
| A `var()` declaration of a class (or its state, or an inline style) whose variables each have one value, defined only on top-level `:root`, `html` or single-class rules or inline styles (or not at all, so the fallback applies), and that resolves the same for every element of the class | Literal value in the class, no Embed copy: the copy would change no value, yet it overrode the class in the editor and every later rule over it. Any other definition of a variable it uses (in a media query, under a relational or state selector, `@property`, an external stylesheet), a second value, or one element of the class outside the defining element keeps the copy (2026-10-19) | — |
| An Embed declaration of a class rule (a `var()` copy, animation, `url()`, auto side margin, unresolved `var()`) that another class rule, an inline style or a breakpoint rule overrides on some elements in the source | The Embed loads after the class rules, so written plainly it would win there (a pill gained the border its modifier removed; an overlay lost its inline `background: none`, 2026-10-19). Every declaration of a class rule (page, lowered selector, inline style, external class) is ranked as in the source cascade: `!important`, inline style, specificity, source order; a media query only decides at which Toolkit breakpoints it applies (`system/lib/css-cascade.js`, which the class order and the Taptop base resets rank with too). The Embed declaration is planned per breakpoint (`planScope`): left out at a breakpoint where its own class overrides it whole; left out on the elements of a class that alone overrides all its longhands (`.pill:where(:not(.pill--crm))`, zero specificity, so a `:hover` state still beats it); and where it loses only in part, the overriding declarations are written right after it, restricted to its elements, in rank order (`.hero:where(.hero--alt) { background-position: top; }`; a later part of the same rule joins its block: `.hero { background: url(…) no-repeat; background-size: cover; }`), so every longhand ends at its source winner and nothing is lost. Breakpoint bands use Media Queries Level 3: `not all and (max-width: 767px)` above a breakpoint, `(min-width: 479.02px) and (max-width: 767px)` between two (`BAND_OFFSET_PX`; the Level 4 range syntax was never tried in a Taptop Embed). Rebuilding changes existing packages: the generated UI kit's `.kit-type-spec { margin-left: auto }` now stops at 479px, where the kit's own `margin-left: 0px` applies (before, the Embed rule beat it and the spec stayed right-aligned on phones), so every project's regenerated UI-kit Embed differs after a rebuild | `EMBED_CASCADE_SCOPED` |
| A rule for a class no element of the page has | Nothing is written: its Embed-only parts (`var()` copies, animation, auto margins) and its custom-property definitions included. Before 2026-10-19 those parts still went to the Embed while the report said `UNUSED_RULE` removed | `UNUSED_RULE` |
| `body` / element rules repeated in the CSS | Cascade order: the later rule wins; class rules still win over both | — |
| A stylesheet or `<style>` ending with an unclosed block | Closed at its own end, as browsers do | `CSS_BLOCK_AUTO_CLOSED` (warning) |
| CSS the browser cannot recover from either | Reported instead of crashing | `CSS_PARSE_ERROR` (error) |
| Unresolved `var()`, `url()` with a full `https://`, `//` or `data:` address | Embed | `VARIABLE_UNRESOLVED`, `URL_TO_EMBED` |
| A relative `url()` anywhere in the Embed stylesheet (except `@font-face`, see `FONT_FILE_RELATIVE`) | Blocked: the file is neither packaged nor uploaded, so the image would be missing in Taptop (a pilot lost its product photos this way while `build` printed no warning, 2026-10-15). Use an `<img>` layer | `URL_ASSET_LOST` (error) |
| `!important` | Removed, value kept. It still ranks first in the source cascade the class order and the Embed are decided by, and a class keeps its `!important` value against a later normal declaration of the same class (2026-10-19) | `IMPORTANT_REMOVED` |
| Vendor-prefixed properties | Removed | `VENDOR_DROPPED` |
| `margin`, `padding`, `border[-side]`, `gap`, `place-items` | Longhands | — |
| `body` text settings | Inherited properties (colour, font, line-height, `overflow-wrap`, `word-break`, `white-space`, `hyphens`, `text-wrap`, `text-shadow`, `font-feature-settings` …) and the background go to the root block | `GLOBAL_RULE_LOWERED` |
| `var(--x)` where `--x` is redefined inside a media query (`@media (max-width: 900px) { #box { --dir: column } }`) | The class keeps the value resolved at desktop; the embed repeats the declaration with `var()` on the same class, together with the variable definitions, so the switch still happens on narrow screens (published page and editor canvas) | `VARIABLE_BY_MEDIA` |
| `@font-face` with a relative font file | Kept in the embed and reported: the file does not reach Taptop; upload the font to the project or use a full URL | `FONT_FILE_RELATIVE` (warning) |
| `font` shorthand (`700 21px/1.2 Inter, Arial`) | `font-style`, `font-weight`, `font-size`, `line-height` (kept as written, see below), `font-family` (first name); `font: inherit` and system-font keywords stay as they are | — |
| Unitless, `%`, `em`, `rem` and fluid (`clamp`, `calc`, `vw`) `line-height` | Kept as written; the compiler stores it as a custom rule, so inheritance and every width behave as in the source | `LINE_HEIGHT_CUSTOM` |
| Inline `style=""` | New class `<class>-inlineN` (no hyphen before the number, see the counter fact) | `INLINE_STYLE_TO_CLASS` |
| Element without class | Class `<parent>__<tag>` | `CLASS_GENERATED` |
| Missing `data-taptop-key` | `<class>-N` | — |
| `#id` in a selector | The element gets a class named after the id (`id-<id>` if that class name is taken) and `#id` becomes that class in every selector; before this, id rules were silently lost because the id is removed | `ID_TO_CLASS` |
| `data-taptop-name="<text>"` on a layer element | The layer's name in the Taptop layer panel: ASCII whitespace trimmed and collapsed to one space; a value of only whitespace, no-break and other Unicode spaces included, counts as absent (a no-break space inside a name is kept). Kept in `page.html`, never written to the package as an attribute and not reported as `ATTRIBUTE_REMOVED`. Inside an SVG icon or a Rich Text layer an element is markup, not a layer: the attribute is removed there without a report item. Without it the layer is named after its first own class ([Layer names](#layer-names)) | — |
| `id`, `role`, `aria-*`, `tabindex`, other `data-*` | Removed | `ATTRIBUTE_REMOVED` |
| Link to a removed `id` | Kept; set the anchor in Taptop | `ANCHOR_TARGET_REMOVED` (warning) |
| `<a>` wrapping elements | Editable link block | — |
| `data-taptop-behavior="accordion"` | `behaviors.json`; panel hide state to Embed | `BEHAVIOR_DECLARED`, `BEHAVIOR_STATE_TO_EMBED` |
| `data-taptop-behavior="menu"` | Toggle (`*burger*`/`*toggle*`), panel (`*sidebar*`/`*drawer*`/`*panel*`), optional backdrop (`*backdrop*`/`*overlay*`/`*shade*`); the script toggles `is-open` on the root, `.root.is-open …` CSS goes to Embed; `data-taptop-anchor-prefix` makes `#name` links scroll to `.<prefix>name` | `BEHAVIOR_DECLARED` |
| Tilda `.t-slds` with more than one `.t-slds__item` | Editable slide layers remain in Root. A generated `taptop/embed-slider-v1` Embed controls arrows, bullets, keyboard navigation and swipe, beginning at the source active slide. Its CSS keeps only the active slide visible. | `TILDA_SLIDER_DECLARED` |
| Tilda `t1196` horizontal card carousel | Editable cards remain in Root. A generated `taptop/embed-slider-v1` Embed scrolls the source card track by one visible card through its controls. | `TILDA_CAROUSEL_DECLARED` |
| Tilda `t-video-lazyload` with an HTTPS `.mp4` source | The lazy shell remains editable; a generated `taptop/embed-video-v1` Embed creates a muted, controlled HTML5 video. A local poster is retained when the source supplies one. | `TILDA_INLINE_VIDEO_DECLARED` |
| Tilda `.t-popup` containing `t1013__html5video` with an HTTPS `.mp4` source | The popup shell remains editable; a generated `taptop/embed-video-v1` Embed opens it from the declared hash link, moves focus, closes by control, backdrop or Escape and restores page scrolling. | `TILDA_VIDEO_DIALOG_DECLARED` |
| Tilda `.t-animate` targets | Editable layers stay in place; a generated `taptop/embed-reveal-v1` Embed adds Tilda's started class as each target enters the viewport and restores visibility if a source effect cannot finish. | `TILDA_REVEAL_DECLARED` |
| Tilda `data-original` lazy images and background images | The prepared image or `background-image` uses `data-original` before source scripts are removed. This replaces Tilda's small blurred placeholder with the original asset. | `TILDA_LAZY_IMAGE_PROMOTED`, `TILDA_LAZY_BACKGROUND_PROMOTED` |
| Legacy `<center>` | Editable `toolkit-center` and `toolkit-centered-block` layers with a generated Embed centering rule. | `LEGACY_CENTER_PRESERVED` |
| Tilda `.t-cover` with a `data-content-cover-bg` carrier | The carrier's original image is promoted to the editable cover, which uses `background-attachment: scroll`, matching the carrier-scoped sizing done by Tilda startup code. | `TILDA_COVER_BACKGROUND_PROMOTED`, `TILDA_COVER_BACKGROUND_SCROLL` |
| Tilda geolocation script with a `geo: ''` default card | Blocks hidden by the default card are removed; the default desktop/mobile pair remains and existing responsive CSS chooses the visible one. | `TILDA_GEO_DEFAULT_APPLIED` |
| `animation` and its longhands | Embed stylesheet; the associated `@keyframes` is already an Embed at-rule. | `ANIMATION_TO_EMBED` |
| `transform-box` (`CLASS_REJECTED_PROPERTIES`) | Embed stylesheet; the class keeps its other declarations. Taptop class sync refused it on a live import (below) | `CLASS_PROPERTY_TO_EMBED` |
| An image whose classes set no `overflow` at screen level (Taptop's image base is `overflow: hidden`) | The browser value `overflow: clip` (or, when the source sets one longhand, the other one) in the Embed stylesheet as `.<class>:where(.image, img)`, never on the class: a value Taptop class sync refuses fails the whole import (`transform-box`, below), and whether it keeps `clip` is unread. The rule is first in the Embed and ranks below every source declaration: it is left out where a class of the element sets overflow, at a breakpoint too (`:where(:not(.x))`, a media band), and a source rule the Embed carries at equal specificity comes after it. `:where(.image, img)` reaches the `tt_image` wrapper the compiler emits and the source `<img>` of the local preview, not a block that shares the class. Written for every image, not only flex and grid items: see the image overflow row in Taptop facts. So every page with an image ships the styles Embed (`page.embed.css`, one hidden Embed in `Scripts` with `toolkit-behavior` and its rule): an image-only page that had none gains that layer and, with an external stylesheet, the `TOOLKIT_CLASS_*` site check; how the importer handles that extra layer on such pages was not observed | `IMAGE_OVERFLOW_TO_EMBED`, `EMBED_CASCADE_SCOPED` |
| `margin-left: auto` or `margin-right: auto`, also as part of a `margin` shorthand (`margin: 0 auto`, `margin: 10px auto 20px`) | Embed stylesheet; native Taptop class controls turn these side margins into `0px`. The shorthand's other sides stay in the class (before 2026-10-19 the shorthand's auto sides went to the class and centred blocks lost their centring). A later rule that overrides one side follows it in the Embed (`EMBED_CASCADE_SCOPED`). `margin-inline: auto` is not touched: the compiler writes it as a custom rule, not through the native margin control (whether Taptop keeps that custom value was not checked live), and `margin-top`/`margin-bottom: auto` (a flex item pushed down) stay in the class as before | `MARGIN_AUTO_TO_EMBED` |
| Legacy vendor properties (`-webkit-*`, `Moz*`, `KHTMLOpacity` …), IE `filter: alpha(…)`, or a nonzero unitless `letter-spacing` | Removed. Modern source equivalents such as `opacity` remain. | `VENDOR_DROPPED`, `INVALID_VALUE_DROPPED` |
| `font-family` stacks | Bare Taptop font name; Google Fonts links kept for local preview only | `FONT_NAME` |
| Width, display, height, position the source left to the browser | Browser value written on the element class against Taptop's layer base classes, with the lowest priority (a real value from another class of the element wins, through an order class if needed). A class shared by elements that need different values takes the most common one; every other group gets `<class>--base[-b …]` (Taptop's own default written out when that group needs it); `TAPTOP_BASE_CONFLICT` remains only when no value can be written | `TAPTOP_BASE_RESET`, `TAPTOP_BASE_VARIANT`, `TAPTOP_BASE_CONFLICT` (warning) |
| An `<img>` whose screen `width` and `height` end up on different classes after selector lowering | Both effective values are repeated on one image size class, which the compiler's image layer requires | `IMAGE_DIMENSIONS_JOINED` |
| `html { scroll-behavior }` | Removed: it freezes the editor canvas | `SCROLL_BEHAVIOR_DROPPED` (warning) |
| Class named like a Taptop system class (layer classes `div`, `text`, `button`, `image` …, `html`/`body`/`head`/`root`, and the names of Taptop's base stylesheet in `system/lib/taptop-base-classes.json`: `section`, `container`, `link`, `badge`, `menu__*`, `slider__*`, `pop-up__*` …) | Renamed to `u-<name>` in the HTML, every selector and the root selector; a clash with an existing `u-<name>` stops normalization | `RESERVED_CLASS_RENAMED` (warning) |
| Class ending in `-0`, `-1` or a zero-padded number (`col-1`, `mt-0`, `step-01`) | The trailing `-` becomes `_` (`col_1`) in the HTML, every selector and the root selector; `-2` and larger stay (`card-pad-12`) | `CLASS_COUNTER_RENAMED` (warning) |
| `<style>` elements in the page (head or body) | CSS joins the cascade after the linked stylesheets, in document order | `STYLE_BLOCK_LIFTED` |
| `<script>` elements | Removed; source JavaScript is never transferred; the behavior they drove must come from a Toolkit behavior or is listed as UNSUPPORTED | `SCRIPT_DROPPED` (warning) |
| `<meta>` inside `<body>` | Removed before layer generation; it is metadata, not a visible layer. Set its SEO or preview value separately in Taptop | `BODY_METADATA_DROPPED` (warning) |
| Tilda `.t-records` root hidden with `opacity: 0` until its source script runs | The prepared root receives a generated Embed style that makes it visible in the static preview and after import. This is a source-page normalization rule; the imported editor still needs checking. | `TILDA_ROOT_REVEALED` |
| `<details>`/`<summary>` | Accordion behavior: details → item, summary → trigger, the rest → panel (wrapped in `<item>__panel` when needed); `open` → `is-open` | `DETAILS_TO_ACCORDION` |
| A visual button whose direct child is an icon or another element | An editable container, retaining its visual class and descendants; it is not compiled as a text-only Taptop Button. | `NESTED_BUTTON_AS_CONTAINER` |
| A container whose children are only inline content, including links and line breaks | One Rich Text layer so the inline flow and link markup survive. | `INLINE_RUN_AS_RICH_TEXT` |
| Whitespace in text content | Only ASCII whitespace (tab, LF, FF, CR, space) collapses to one space and is trimmed at a layer's edges, as in the browser. U+00A0 no-break space and the other Unicode spaces are text: kept inside, at the start and at the end of a text, a wrapped text run and a `<details>` panel, and counted as visible text in every layer decision (a no-break space beside block children is `MIXED_CONTENT`). Text nodes split by a comment join without a space. A class attribute splits on ASCII whitespace only too, so a class token holding U+00A0 stays one class. One helper owns this: `system/lib/html-whitespace.js`; JavaScript's `\s` and `trim()` also match U+00A0 and must not be used on text | — |
| Text beside other elements inside a flex/grid container (e.g. a label next to an icon) | Wrapped in its own text layer `<class>__text`; a flex/grid item already renders this way, so the layout is unchanged | `TEXT_RUN_WRAPPED` |
| Inline `<svg>` | One SVG Icon layer (`tt_svg_icon`) holding the SVG markup; its source `width`/`height` are written on the layer class (the Taptop default is 32×32) | `TAPTOP_BASE_RESET` |
| Text with inline formatting (`strong`, `em`, `u`, `s`, `br`, inner `span`, `a` …) outside a flex/grid container | One Rich Text layer (`tt_rich_text`) with the inner HTML verbatim; a link becomes a link block holding it | `RICH_TEXT_LAYER` |
| Classes and element rules that only style markup inside a Rich Text or SVG Icon layer | Embed stylesheet (it also applies in the editor canvas) | `INNER_STYLE_TO_EMBED` |
| Class rules of one breakpoint | Written in Taptop's order (class name, `localeCompare`), so the preview shows Taptop's cascade. | A page class and an external class of one element set the same property with different values | No order class (none named after a page class can sort after the site class); reported. Two external classes competing are the site's own cascade and are left alone | `EXTERNAL_ORDER_UNVERIFIED` (warning) |
| Page rule whose subject carries an external class: `.name`, `.name:hover`, `.name::after`, `.page.name`, `.card .name`, in any `@media` or `<style>` block | Blocked: the package must not restyle a class the target site owns. A state class taken from the source is renamed in the source; the Toolkit's fixed names (including the `is-open` an open `<details>` gets) are not renamed automatically, because the page's CSS is written against them | `EXTERNAL_STATE_CLASS` (error) |

## Layer names

The compiler names each layer (`tag.name`, what the Taptop layer panel shows) by its IR `name` (`data-taptop-name`, `system/lib/compiler/html-to-ir.js`), else by its last class (`system/lib/compiler/ir-to-taptop.js`, every layer kind: div, text, Rich Text, SVG Icon, button, link, link block, image). The last class is often one the normalizer appended: a lowered selector's `<first matched element's class>--sel` lands on every element the selector reaches, so before 2026-10-19 dozens of layers of one imported block carried the same name. The normalizer therefore picks the name (`layerNameClass` in `html-normalizer.js`), in this order:

1. The element's first own class: not external (a class of `--external-css`), not a Toolkit class (`system/lib/toolkit-classes.js`), not the `is-open` class an open `<details>` gets, and not made by the class namer.
2. Else its first structural class: one the namer made to give an element its own identity, `__<tag>` (a classless element's `<parent>__<tag>`), `__text` (a wrapped text run, a link's Rich Text span) or `__panel` (a generated `<details>` panel). A classless `<p>` that a lowered `.wrap p` reaches is `a__p a__p--sel` in one parent and `b__p a__p--sel` in another; they are named `a__p` and `b__p`.
3. Else its last class, as before (an element with only site classes, only Toolkit classes or only lowering classes).

The namer's other classes are lowering and ordering classes (`--sel`, `--inner`, `--base`, `--order`, `--size`, `-inline<n>`): one lowered selector puts the same class, named after the first element it reaches, on every element it reaches, so such a class names a layer only under rule 3. Every namer class, with its `-b`, `-c` … variant, is tracked by the name it was made under (`createClassNames`), so a source class that happens to end in `--sel` is an own class and names its layer, and a generated class that a source-class rename touches keeps its kind under the new name. A source class renamed by the normalizer (`u-<name>`, `col_1`, an id class) is an own class under its new name. `data-taptop-name` is written only where the chosen class differs from the last class.

The `compile` command compiles prepared HTML without the normalizer: there `data-taptop-name` names the layer as well, and a layer without it is named after its last class, since nothing picks a class (`system/test/layer-names.test.js`).

Source modifiers after the first class no longer name the layer either: a page's `btn btn--secondary` is named `btn`. Give a layer `data-taptop-name` where the first class does not identify it. The generated UI kit does so on every element with more than one class (`serializeHtml` in `system/lib/ui-kit/markup.js`): it writes the block first and the modifier or role last (`kit-section kit-section--type`, `kit-type-sample type-title`, `btn btn--secondary`), so its layers keep the last-class names they had before 2026-10-19. A kit generated before that carries no `data-taptop-name`; until it is regenerated (`ui-kit … --replace`) its layers are named after their first class. Test `system/test/layer-names.test.js` pins which fixture names changed.

No length limit is applied: nothing in the Toolkit or the importer constrains `tag.name` (checked 2026-10-19), and Taptop's own limit, if any, has not been tested live. Nor is the set of characters limited: how Taptop shows a name with quotes or angle brackets (`"`, `<`, `>`) has not been checked live either. The importer's class-conflict copies rename a layer whose name equals a renamed class (`class-conflicts.js` in the importer), which still holds for a name taken from a class.

## External stylesheets

`artifact add … --external-css <file.css>` (repeatable) registers the target site's own stylesheet, for example the class library of a Taptop site whose classes were built in the editor. The registry field is `externalStylesheets`; the files are build inputs (an edit makes the result stale) and are linked, not copied: `page.html` and `original.html` load the project file first, by a relative path, so the comparison sees the site styles on both sides.

- A class is external when the sheet has a single-class rule for it, optionally with a state, at the top level or inside a top-level `@media`. Compound and relational selectors (`.tab.is-open`, `.card .title`) and pseudo-elements do not make a class external; they still apply in the preview.
- Taptop system names (`system/lib/taptop-system-classes.js`) are never external: a page using one is renamed to `u-<name>` as usual (`RESERVED_CLASS_RENAMED`) and loses the site's rule for it. Use another site class or a page class.
- The Toolkit's own class names (`system/lib/toolkit-classes.js`) are checked against the sheets for every one the package uses: on its layers, in its Embed stylesheet, a behavior's runtime class, and `toolkit-behavior` whenever the package carries an Embed (a behavior or the Embed stylesheet). A site that defines one exactly as the Toolkit does passes (`TOOLKIT_CLASS_ON_SITE`); any other site rule for it stops the build (`TOOLKIT_CLASS_CONFLICT`), the reason quoting the Toolkit's rule and the source the site's rules. A package without an Embed does not use `toolkit-behavior`, so the site's rule for it is not checked. Found 2026-10-16: a live site's shared stylesheet defined `.toolkit-behavior {display: none;}` after Toolkit packages with behaviors had been imported there; before this check, a site rule `display: block` for it built and passed preflight and the importer's inspector silently.
- An external name is referenced as it is: no `CLASS_COUNTER_RENAMED`.
- Every generated class goes through one namer (`uniqueClassName` in `html-normalizer.js`): `<base><suffix>`, or `<base><suffix>-b`, `-c` … when the name is taken by a class of the page, of its CSS or of any selector of the external sheets (compounds such as `.tab.is-open` included). The base is a page class or a tag, never an external class. This covers `--sel`, `--inner`, `--base`, `--order`, `--size`, `-inline<n>`, `__text`, `__<tag>` and `__panel`; id classes avoid the external names as `id-<id>`. Elements that ask for the same `__<tag>`, `__text` or `__panel` share one name. The guard against page classes applies without external sheets too: a page that already has `card__panel` gets `card__panel-b` for a generated `<details>` panel instead of sharing the page's class.
- Custom properties in external class rules are resolved from the sheets' top-level `:root`/`html` rules for these cascade decisions; a value that still holds `var()` is left out of them (it cannot be compared).
- Every class the package selects by is a page class: behavior targets (`reveal` target, `menu` root/toggle/panel/backdrop, `accordion` root/item/trigger/panel and the open-state class, `steps` root/item/panel/copy and hidden classes), the root selector in `manifest.json`, the Tilda reveal root class (an external `--root` class is replaced by `toolkit-tilda-root`), the `<details>` panel class and the compiler's `<class>__fill` class of link and button layers.
- Values or selectors the package needs on an element whose classes are all external stop the build (`EXTERNAL_ONLY_ELEMENT`, the reason names what needs the class: a value, a behavior, the root selector, the fill class): give the element its own page class next to the site classes. The compiler refuses the same for a root selector or a link/button fill.
- Preflight also refuses a behavior Embed that targets an external class (`targets external class`), so a new place that picks a site class is caught before import: a rule of its CSS with an external class as subject; in its script, a `*Class` value of `const config = {…}` naming one or a `*Selector` value whose subject has one; a script without that config object is read string by string (both quote kinds), each string as a name and as a selector. When the config object exists, literals outside it are not scanned.
- The compiler writes no rule, identity or `syncPackage` entry for an external class and refuses any selector entry that reaches one (`EXTERNAL_CLASS_REDEFINED`). The package wrapper lists the classes layers use as `externalClasses: [{ "name", "collection" }]`, sorted by name; preflight checks each is one clipboard class, unmanaged and without rules. The package version stays 2.
- The importer must check that each listed class exists in the editor before it writes anything. An importer that does not know the field imports the layers with the class names and does not check them.

## Accordion contract

Root marked `data-taptop-behavior="accordion"`; each direct child item holds a
trigger (`role="button"` or a class like `*trigger*`, `*question*`) and a panel
(`role="region"` or `*panel*`, `*answer*`). The class present on only some items
is the open state (default `is-open`). Items, triggers and panels must share a
class each. The Embed script restores `role`, `tabindex`, `aria-expanded`,
click and Enter/Space handling on the published page; every answer stays
visible and editable in the editor.

## Steps contract

Adapter `taptop/embed-steps-v1` (`system/lib/steps-embed-code.js`), made for
animated design-canvas boards whose state a script switches. The root carries
`data-taptop-behavior="steps"`, its config as JSON in `data-taptop-steps`,
and the classes of state 0 (the editor and visitors without JavaScript show
it). The config is refused (`STEPS_CONFIG_INVALID`) on any unknown key or
wrong type:

| Key | Value |
| --- | --- |
| `rootClass`, `itemClass` | Class names; the items are matched in DOM order inside the root, their number is `count` |
| `count` | Integer, at least 2 |
| `statePrefix`, `fromPrefix` | Prefixes of `is-`/`has-` names: state `n` is `<statePrefix>n`, the state switched from is `<fromPrefix>n` |
| `backClass`, `autoClass`, `manualClass`, `copiedClass` (optional) | `is-`/`has-` class names on the root |
| `startedClass` | `"is-inview"` |
| `intervalMs` | Positive integer: autoplay period |
| `onManual`, `pauseOnHover`, `pauseOnFocus` | `"stop"`, `true`, `true` |
| `pattern` | `"stepper"` or `"tabs"` |
| `labels` | `count` non-empty strings: each item's accessible name |
| `hiddenClasses` | Class names of decorative layers (`aria-hidden="true"`), may be empty |
| `panelClass` (optional) | Panel `n` in DOM order belongs to state `n`; used only for the tabs ARIA (`role="tabpanel"`, ids) |
| `copyClass`, `copiedClass`, `copyTexts`, `copiedMessage`, `copyLabel` (optional, all or none) | The copy control's class; the `is-` class it puts on the root; `count` strings, the text copied in each state (real spaces and `\n`, written verbatim); the live-region announcement; the control's `aria-label`. The texts come from the config, not the DOM: a code panel built from line layers (a line number and the code per line) does not give its code back as `textContent` or `innerText`, and Taptop's published shape of those layers is unverified. Messages and labels are the converter's, so the adapter core holds no page language |

All state classes must be `is-`/`has-` names so that the normalizer keeps their
rules verbatim in the Embed stylesheet, and all classes of one config must be
distinct.

On the published page, per root: when the script binds the root (on
`DOMContentLoaded` while the document is loading) it sets state 0 and all the
ARIA below, so the items are reachable by keyboard before the block has been in
view. When the root first enters the viewport it gets `startedClass` and
`autoClass`; every `intervalMs` it moves to
`(i + 1) % count`. Switching to `i` removes every other state and from class,
adds `<fromPrefix><previous>` (none on the first start) and adds `backClass`
when `i` is lower than the previous state, except last → first (with
`count` 2, 1 → 0 is never back), for autoplay and manual selection alike: the
board CSS is written against the canvas logic that does exactly this. Autoplay
pauses while the pointer is over the root, focus is inside it or it is out of
view, and resumes with a full interval. A click, Enter or Space on an item (on
tabs also ArrowLeft/ArrowRight, wrapping, and Home/End, each moving focus) shows that state,
swaps `autoClass` for `manualClass` and stops autoplay on that root for good;
done before the first entry into the view, the entry then only adds
`startedClass` and keeps the selected state.
With `prefers-reduced-motion: reduce` the root stays at state 0 with
`manualClass` and no timer; clicks still work. A root whose item count differs
from `count` is left as it is. ARIA, set at bind and on every switch:
stepper items get `role="button"`, `tabindex="0"`, `aria-label` from
`labels`, `aria-current="step"` on the active one; tabs get `role="tablist"` on
the items' common parent, `role="tab"`, `aria-label` from `labels`, `aria-selected`, a roving `tabindex`,
`aria-controls`/`aria-labelledby` with generated ids
(`taptop-steps-<rootClass>-<n>-tab-<k>`, `-panel-<k>`; `n` is a counter on
`window.taptopStepsIdCounter` shared by every steps Embed of the page, so the
ids stay unique across Embeds and repeated blocks) and `role="tabpanel"` on
the panels. Whether an inactive panel is hidden, also from assistive
technology, is the page CSS's job (the canvas boards use `visibility: hidden`,
which removes it from the accessibility tree); the adapter does not set
`aria-hidden` on panels. The copy control (`role="button"`, `aria-label` from
`copyLabel`, Enter/Space too) stops autoplay for good like an item click but
keeps the state, writes `copyTexts[state]` through
`navigator.clipboard.writeText`, then adds `copiedClass` to the root for
`COPIED_MS` and says `copiedMessage` in a polite live region (one per root,
appended to `body` at bind): it empties the region and writes the message
`REANNOUNCE_DELAY_MS` later, so a repeated copy is announced again; both are
cleared `COPIED_MS` after the write. The script binds a root once
(`data-taptop-steps-bound`), so a second copy of the Embed on the page does
nothing. The config is written with `<`, U+2028 and U+2029 escaped. A root
skipped for a wrong item count is not logged: no Toolkit adapter has a debug
log to follow. A rejected or missing clipboard write
adds no class and says nothing; autoplay stays stopped. Locally tested against a synthetic DOM only (`system/test/steps-embed-code.test.js`).

## Known limits

- Embed scripts run on the published page only; embed CSS also applies in the editor canvas.
- Preflight's external-class check of a script reads `*Class` string values of its config object. The steps config also names classes as `hiddenClasses` (an array) and as prefixes; the normalizer refuses external ones there (`STEPS_CONFIG_INVALID`), but preflight does not see them in a package built elsewhere.
- The Toolkit-class check (`TOOLKIT_CLASS_CONFLICT`) sees only site rules that name a Toolkit class. A generic site rule can also reach the behavior Embeds and show or move them: a universal or type selector (`.site-wrap > *`, `div`), an attribute selector without a value (`[class]`), `:nth-child()` on the Embeds' parent. No name check sees those; compare the page in the editor.
- A no-break space (`&nbsp;`, U+00A0) is visible text (2026-10-16). Directly inside a container next to block children — a stray `&nbsp;` between two `<div>`s, common in Tilda and other builder exports — it is `MIXED_CONTENT` and stops the build, where earlier versions dropped it silently. Remove it from the source if it is not meant to show, or put it in its own text element; inside a flex or grid container it becomes its own text layer (`TEXT_RUN_WRAPPED`), next to inline elements one Rich Text layer.
- External classes and class order (not verified live): whether a site's class library and imported classes share one name order on the canvas and the published page is unknown (the site's published library is not in name order). When a page class and an external class of one element set the same property, the source gives the page value; the package cannot force it, because an order class would have to be named after the site class. The build reports `EXTERNAL_ORDER_UNVERIFIED`; check those elements in the editor.
- A Taptop system name that the external stylesheet also defines (for example `text-secondary`, which is in Taptop's base stylesheet) is not treated as a site class. The page's use of it is renamed to `u-<name>` (`RESERVED_CLASS_RENAMED`), so the site's rules for that name are lost on that layer. The reason: Taptop's base stylesheet styles these names after the project rules, so the site's rule cannot be relied on. Use another site class or a page class for those values.
- Open question (2026-10-09, needs a live import): an `<img width height>` inside a stretching flex column keeps its size in the original, but the normalized class gets `width: auto; height: auto` (`TAPTOP_BASE_RESET`) and the local preview stretches it to the column width. The package sets the `tt_image` `maxWidth`/`maxHeight` to the intrinsic size, which `taptop-preview.css` does not emulate. Until the editor result is observed, treat such an image difference in the comparison as unresolved, not as a pass.
- Open question (2026-10-21, needs a live import): whether the image overflow Embed rule (`IMAGE_OVERFLOW_TO_EMBED`) takes effect on a published page and in the editor canvas. It relies on three things not read live: the Embed `<style>` comes after Taptop's image base (`.image { overflow: hidden }`, equal specificity) — the local preview links `page.embed.css` last, and the Embed cascade scoping (`EMBED_CASCADE_SCOPED`) makes the same assumption about class rules; the `tt_image` wrapper carries the layer's classes and the system class `image` (`buildImage` in `system/lib/component-builders.js`, from a native-copy export); and the base sits on that wrapper. If the Embed loads earlier, the base `hidden` stays and the image shrinks in a flex or grid parent as before this rule; the import itself is not at risk. The inner `img` (`image__img`, which carries the layer's classes too) also gets `clip`, the browser's own value for it. A further assumption: in Taptop the flex item is the `tt_image` wrapper (`.image`, `buildImage` in `system/lib/component-builders.js`), not an `<img>`. With `clip` the wrapper's automatic minimum width comes from its content, the inner `img.image__img`, whose min-content width depends on Taptop's base for `image__img` and on which layer classes (width, height) reach the inner `img` — none of it read live. The 230/200/230 measurement (image overflow row in Taptop facts) was taken on a bare `<img>` only, so on Taptop the rule may turn out a harmless no-op. Verifying it needs only a read of an image already published on Taptop: the wrapper's and the inner `img`'s classes and the computed styles of `image__img`; no publishing. `clip`, not `visible`: `visible` lets `object-fit: cover` content paint outside the image box (a 3:1 picture in a 100×100 `object-fit: cover` image painted 50px beyond the box with `visible`, nothing with `clip` or `hidden`; headless Edge, 2026-10-21). Check after the first import: an image in a narrower flex tile keeps its source width on the published page.
- The source-cascade ranking of Embed declarations (`EMBED_CASCADE_SCOPED`) covers class rules, lowered selectors, inline styles and external class rules at the Toolkit breakpoints. It does not rank `:hover`/`:focus`/`:active` state rules (an Embed copy of a state rule is written as before), rules the Embed carries whole (other media queries, relational selectors left in the Embed: they compete with the copies inside the Embed by their own order and specificity) or element rules (below every class rule, they never win against one, except an `!important` element rule, which the class layer does not honour either). Logical properties (`margin-inline` …) are compared as their own longhands. That the Embed loads after the class rules in Taptop was not checked in the live editor: the local preview links `page.embed.css` after `page.css`, and the defect was seen there (2026-10-19).
- Embed CSS targets class names; if Taptop renames a colliding class on paste,
  the matching Embed rules stop applying. Prefer unique source class names.
- Taptop keeps an existing project class with the same name on paste; class updates go through the runtime class sync, never through paste.
- Re-import receipts live in the editor browser's localStorage: another browser or a cleared storage treats the next import as a first one (same-name classes → choice).
- State rules in the `cm` channel are compiled from an existing contract; their
  editor rendering needs a live receipt per new state type.
